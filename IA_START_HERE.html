01

The project in one minute

This repository contains a complete desktop experience, its installer and its updater. The existing implementation is the starting point for new work.

The experience

Polished, coherent, practical

A Windows-familiar launcher and file browser, a per-display taskbar, coordinated themes, a Control Panel, settings, wallpaper tools, file-transfer popups, recording, native effects and KVM management.

The design goal is rich functionality with clear everyday controls. New surfaces should feel like part of the same desktop and follow its active theme.

The implementation

Native tools working together

Hyprland handles windows and workspaces. Python/PyQt6 powers much of the shell; Qt/C++ powers Control Panel and Fusion Files. KDE KIO handles file jobs, with kio-admin for authenticated copy/move; a bounded authenticated helper handles protected removal and restore. GTK powers Setup; Bash ties launchers and session helpers together.

Shared theme, runtime and update code keep these separate applications coordinated.

The development computer also runs this desktop. Public changes belong in config/hypr/ and the appropriate installer/docs/tests directories. The running copy under ~/.config/hypr/ contains personal state as well as installed code. A change in either copy does not automatically change the other.

Scope of this guide: a source-based handoff checked on 1 November 2026, including the file-manager and minimize-icon improvements. Read current code, manifests, Git status and the user's latest request before editing. This page is a map, not a claim that all tests have just run or that every future checkout matches this snapshot.
02

A fresh context starts here

  1. Locate the checkout and see what is already changing.

    The usual workspace is ~/Desktop/x_hyperland. Check for applicable AGENTS.md instructions, then inspect Git status and recent commits. Preserve work already present.

  2. Identify the application and its actual entry point.

    Use the map below. “Fusion Settings” is control_center/; “Control Panel” is control_panel/. Fusion Files is file_manager/; file-transfer windows are file_jobs/.

  3. Compare source and installed behavior.

    A running preloaded UI can still contain old code. Follow its wrapper, binary and session owner before concluding that a source edit failed. Keep a backup before changing the live copy.

  4. Carry the change through the full path.

    Consider appearance, behavior, saved state, fresh-install defaults, update ownership and relevant tests. Record what was changed and verified for the next session.

What happens when Hyprland starts

  1. hyprland.conf loads the desktop environment, keybindings, display/input/workspace settings, appearance and startup window rules. Its main helper entry point is scripts/session.sh. The Welcome scene has a separate exec-once entry.
  2. session.sh takes a per-instance lock and activates an already prepared update before starting its helpers or native effects. If code was replaced, it reloads configuration and re-executes the session helper.
  3. It starts the update watcher, theme rebuild check, effect controllers, startup applications, cached UIs, switcher, drag helper, transfer service, taskbar supervisor, wallpaper renderer and desktop menu. Notification, network and authentication helpers respect existing owners.
  4. session_ui/preload.py keeps Apps, Fusion Settings and Control Panel ready without mapping their windows. Requests reveal or focus these instances. Closing a panel can hide it while its process remains alive.
  5. Helpers follow the current compositor's IPC connection. Logout or a compositor exit ends owned processes. The desktop does not depend on an always-running global helper service.

Theme and desktop isolation

desktop/environment.conf and theme/runtime.py provide profile-local application data, Qt plugins, fonts, colors and cursors. Launch through the existing scripts/ wrappers and theme runner so applications receive the correct environment. Shared KDE/Plasma settings are normally left alone.

Two deliberate exceptions are user-requested account-wide Default Apps changes and explicitly selected administrative operations such as optional Fusion sign-in. A new decorative UI should not require global theme changes.

05

One visual language

Appearance is shared infrastructure. Use it when adding a window, menu, dialog or progress surface.

Design + palette

Theme collections, three color modes

Xetal World contains Xetal Raw raw, Xetal Modern modern, BreakPoint breakpoint and Binary Knife binaryknife. Atmospheres begins with Tidal Glass tidalglass, a luminous ocean theme. Collections hold up to four themes, each with Dark, Light and High contrast modes.

Navigation layout is separate: Classic tabs, Modern icon rail, Gallery sidebar or Studio ribbon. Components such as Start menu, switcher and transfer cards can follow the desktop or use a chosen style.

Read → draft → apply

State is more than a stylesheet

theme/state.json selects the look. palettes.json, designs.py and layouts.py define it. draft.py and backend.py manage edited choices and apply selected components.

runtime.py, run.py and the native Qt theme plugins carry colors, fonts and environment into applications. Generated output is not the first place to implement a new theme rule.

Tidal Glass: tidalglass.py defines pearl glass, aqua edges, translucent Settings and Apps surfaces, taskbar and notification styling, and compositor blur, shadows and motion. Selecting its preset suggests Light mode and Gallery sidebar navigation; an existing High contrast choice is retained. File Transfer has a drifting-current scene, and the cursor component uses a pearl pointer with a restrained aqua glow. The three original wallpapers under wallpaper/tidalglass/ are assigned left to right through the existing monitor-set system. Their built-in image generation prompts are recorded in prompts.json. Kitty always uses the matching dark palette, even with a Light desktop, and existing profile terminals reload their colors without restarting their shells. Add future themes through designs.COLLECTIONS and the shared style, palette, surface and wallpaper registries; do not add nonfunctional placeholder cards.

For Python widgets, follow neighboring components' use of the shared runtime and window chrome. For C++ windows, follow the existing palette and appearance integration; Fusion Files has appearance.py and live theme refresh. Keep layout, hover, selection, disabled text and icon contrast readable in all supported modes.

theme/build.py builds the local Qt/GTK integrations. Wallpaper, cursor, taskbar, terminal and notification outputs also have their own generation paths. Check file_policy.py before treating a generated color file as release-owned source.

06

Fusion Files & file transfers

The custom file manager already exists. It is Qt/C++ with KDE Frameworks 6 KIO, built as file_manager/.build/xetal-files. Extend this implementation.

Launch placement: ordinary Files icons and Super+E open tiled; Ctrl-click or the shortcut's floating property uses the launcher's centered floating exec rules and size memory. FileManager1 folder/reveal requests pass --external; direct --select and desktop associations with a folder URI also select that role. Before creating a window, main.cpp assigns xetal-files-external so Hyprland floats and centers it on its first map. window.cpp restores only the external role's saved size (external/size), never its old maximize state. Main Files windows skip generic window-memory restoration; child dialogs and other apps retain it. Keep these modes separate to avoid visible resizing after opening.

Open and save dialogs: picker.cpp reuses Fusion Files in --picker mode. JSON arrives on stdin; one JSON response returns file URIs, the chosen filter and application choices. Selecting an executable returns the file without running it. Desktop, drives, quick access, typed paths, thumbnails and preview are available. Multiple selection, folder selection, save extensions, overwrite confirmation and cancellation have native tests.

file_manager/portal.py implements the standard XDG FileChooser backend (org.freedesktop.impl.portal.desktop.fusion). Hyprland-only configuration and D-Bus activation live under desktop/data/xdg-desktop-portal/ and desktop/data/dbus-1/services/. Keep screen sharing and other portals with their existing backends. Portal-aware Chrome/GTK/sandboxed apps use this chooser; theme/file_picker.hpp also integrates native Qt 5/6 dialogs through the private platform theme. Apps explicitly drawing embedded dialogs can bypass these mechanisms. Existing portal processes read backend selection at startup: log out/in after introducing the backend; do not restart shared portal services.

Window size memory: runtime/window_memory/service.py records regular windows' floating/tiled/maximized/fullscreen mode and normal size. A pinned native adapter identifies transient dialogs and restores fullscreen state by address without stealing focus. Restore mode first, wait for the compositor layout frame, then restore floating size within app and monitor limits. Tiled windows use the current shared layout: never restore their old pixel sizes, because that resizes sibling splits and can squeeze another window into a narrow strip. File pickers always float and synchronously save their actual size on acceptance/cancellation in file_manager/state/settings.ini, separately by application and open/save/folder mode. The memory service observes existing windows without repositioning them at startup and ends with the compositor socket. Its atomic runtime/window_memory/state/windows.json contains hashed identities and geometry, never titles or document paths; never publish it. Explicit launcher floating shortcuts retain their existing sizing.

The intended experience

  • My Computer is a fresh-install favorite with a Linux/penguin computer icon. It opens This PC. The main area has mounted internal disks first, USB devices second, wholly unmounted internal disks last. Every physical disk has one framed row containing all its partitions, largest to smallest; a partially mounted disk stays together in the mounted section. Rows scroll horizontally without wrapping. Their accent background and shared QGroupBox corner styling follow the active theme, including future themes.
  • The sidebar shows mounted volumes below This PC, standard XDG folders and custom quick-access pins, Network and Trash, then unmounted drives. Empty sections in the main drive view and their extra splitters hide automatically, returning when matching drives appear. Group expansion, splitters and layout persist.
  • An accurate address bar supports breadcrumbs and typed/copied paths, including spaces, Unicode, # and %. Tabs, a folder filter, a preview pane enabled on fresh installs, optional picture thumbnails, three icon sizes, list and configurable details views are implemented.
  • Menus expose the default app name, Open with…, Execute for scripts/executables, Cut/Copy/Paste, rename, Trash, properties and Ark compression/extraction plugins. Users can reorder, hide, relabel or add actions.
  • Drive properties show used/free/reserved space, capacity and device details in a compact themed window. System Cleaner opens the Control Panel cleaner page; it does not start cleanup.

Copy/paste behavior that must survive future changes

Copy then paste into an occupied destination automatically keeps both: photo.png becomes photo_copy1.png, then photo_copy2.png. Directories, dotfiles and compound extensions are handled too. Folders get a new numbered directory rather than silently merging. Cut/paste preserves an existing destination. Ordinary collisions do not open a naming dialog; actual transfer errors still report failures.

A paste remains a KIO job with clipboard integration and one Undo operation. Large jobs appear through file_jobs/service.py using the user's File Transfer style, with pause, resume and cancel. Closing the last browser window keeps tracked jobs alive. Avoid replacing this path with a separate raw file-copy loop that bypasses KIO.

Selection regression to remember: a real click in the icon view selects the name cell, not a complete multi-column row. The old use of selectedRows(0) made menus and F2/Delete/Ctrl+C appear broken. The current selection path uses the selected name-column indexes. Test with actual mouse clicks and keyboard events in each view; selecting an item programmatically can miss this bug.

Execution and app opening: double-click or Enter runs recognized local executables with executable permission, including shebang-based installers. The context menu’s Open with [app] always uses that app. Scripts also have an explicit Execute action and run via their declared interpreter or the .sh fallback in a terminal that retains output. Permissions are not silently changed. The searchable chooser in applications.cpp/.py uses Gio discovery and shares Default Apps’ guarded association saves; custom commands do not use shell expansion.

Preferences and deletion: the ⋮ menu includes Configure Fusion Files for thumbnails, the preview pane, hidden files and Trash animation. removal.cpp coordinates ordinary KIO operations and authenticated permission retries through privileged.py. Existing account-owned Trash directories are secured to mode 700 before use, including directories created at 755 by other managers. Protected items retain standard Trash records and can be restored with authentication; permanent deletion remains explicit. trash_animation.cpp animates only successful moves. Private settings remain under file_manager/state/.

Storage: discovery never mounts disks. Mounting, force mounting and permanent deletion retain their explicit action/error paths. Trash failure must not become silent permanent deletion. Paste into a drive verifies that it is still mounted; encrypted and unformatted volumes remain visible for management.

07

Default Apps & folder routing

Control Panel → Software & maintenance → Default Apps is implemented in default_apps.cpp/.h, with default_apps.py as the Gio/MIME backend. Its tile is registered in tools.json and its native page is connected through native.cpp. Fusion Settings → Default Apps uses control_center/default_apps_page.py with the same backend, searchable app choices, Undo and a link to advanced file types.

GRUB Boot Editor lives in control_panel/grub_editor.cpp/.h with grub_editor.py as its authenticated helper. The first tab, Current Grub, parses the installed menu and submenus; it edits names, optionally edits boot commands, and removes entries with validation, backups and Undo. Fusion entries also update their own generator; system-generated edits affect the current configuration and can be replaced by GRUB regeneration. The Add Entry tab lists mounted and unmounted disks; Properties shows disk identity and every partition. Detection uses private read-only mounts, finds EFI loaders and Linux GRUB menus in UEFI and BIOS mode, and skips reserved areas. Saving adds a UUID-based entry while preserving existing entries, theme and default. Tests use disposable files and QEMU images; check_grub_boot.py checks EFI chainloading, missing disks, Linux menu loading and edited menus under UEFI and BIOS.

Twelve everyday categories cover browser, email, file manager, music, video, images, PDF, text, archives, documents, spreadsheets and presentations. A separate searchable view covers individual file types and link protocols. The chooser offers recommended and all installed apps; changes require the user's Use app action. Cancelling or just opening the page leaves associations unchanged.

Follow the user's choice

Generic “open folder”

scripts/file-manager.sh → default_apps.py open-folder → chosen handler, with Fusion Files as fallback. Super+E, Apps → Files and screenshot/recording Show in folder actions use this path. Reveal actions pass --select; helpers explicitly load the profile app-search paths so older background environments do not fall back to another file manager. A running notification helper predating a code update must be restarted to use its new action handler.

A fresh profile selects Fusion Files. A later explicit choice of Dolphin or another manager remains effective. scripts/session.sh starts files.sh --service before startup apps to own org.freedesktop.FileManager1 even with no Files windows open. This also handles Chrome's OpenURI.OpenDirectory portal, which forwards to ShowItems. A profile-local D-Bus service file alone is insufficient because the shared user bus has its own activation search path. ShowItems/ShowFolders in main.cpp resolve the selected handler on every request and forward activation tokens; the service exits with Hyprland. test_service.py checks routing, ownership conflicts and lifetime on a private bus.

Open a specific product

Explicit Fusion Files

scripts/files.sh → file_manager/launch.py → .build/xetal-files. My Computer passes --this-pc; the explicit Fusion Files app always opens this browser.

scripts/dolphin.sh opens Dolphin's isolated profile. These explicit launchers should not recursively route through the generic default.

Explicit changes update standard account-level MIME associations, normally ~/.config/mimeapps.list, along with the relevant existing profile fallbacks. Browser selection coordinates HTTP, HTTPS and HTML; media categories cover registered formats. Applications with their own internal overrides may still use those preferences.

The backend preserves unrelated associations, detects concurrent edits, uses locks/atomic writes and supports Undo. Undo refuses to overwrite later external changes. Its private change record lives in control_panel/state/default-apps/. Never ship the developer's selected apps or Undo history as public defaults.

08

Setup & the pinned runtime

x_hyperinstall.sh runs as the ordinary desktop user. It opens the GTK wizard by default in a graphical session; --cli selects the terminal flow. Privileged package/login work uses separate helpers. A complete clone or extracted source ZIP is required.

installer/install.py renders @HOME@/@HYPR@ paths, detects monitors, seeds clean launcher defaults and recipient Places, compiles native components and verifies the full configuration before activation. Existing profiles are backed up. Graphical Setup detects a registered installation and offers preservation of existing preferences; retain that choice for normal desktop updates.

Fresh-install favorites: My Computer, Kitty and Calculator. The code authority is installer/install.py → LAUNCHER_DEFAULTS. Personal favorite layouts, shortcuts and pins are not copied from the development desktop. Updates preserve users' existing choices.

Runtime compatibility is intentional

At this snapshot, runtime/manifest.json selects Hyprland 0.56.2, exact commit efb50993780079460b0cbed1363e2166a2de1d9f; the Arch package is 0.56.2-4. Read the current manifest before a runtime change. Native effects depend on matching headers and ABI, not just a similar version number.

Optional sign-in and recovery

Fusion sign-in is a separate, initially disabled opt-in using greetd, PAM and an unprivileged greeter. It changes system login configuration only when selected, with backups and a recovery path. It is distinct from the Welcome dashboard. The installer labels sign-in as tested on Arch with SDDM only; consult INSTALLER.md for the exact changed paths and recovery procedure.

Profile backups and Setup logs live under ~/.local/state/xetal-hyprland/. Privileged runtime recovery records use /var/lib/xetal-hyprland/; Fusion sign-in has its own /var/lib/xetal-fusion-login/ backups. Restore the recorded compatible profile/runtime pair rather than guessing at replacement package versions.

09

How public desktop updates work

The updater watches XetalEngine/x_hyperland → main. Every eligible new descendant commit can become a desktop update; a GitHub Release tag is not required.

  1. Check and notify.

    The session watcher checks about every 15 minutes after a startup delay. Automatic updates are enabled by default. The available-update badge is shown for at least 30 seconds before automatic preparation begins.

  2. Prepare the exact announced revision.

    Download into a private cache, apply file ownership rules, merge preferences, rebuild native components and validate the candidate. The updater does not pull/reset the developer's working clone.

  3. Show ready, or require foreground Setup.

    A prepared desktop shows UPDATE READY. A mismatched compositor/runtime shows SETUP REQUIRED instead; background updating does not elevate privileges or replace system packages.

  4. Activate at the next Hyprland login.

    Activation runs before session helpers and native effects. It checks for settings changed since preparation, writes a journal and backup, and applies the prepared transaction. It does not automatically reboot or force logout.

  5. Recover or roll back when needed.

    Interrupted activation is recoverable. A requested rollback is queued for login, pauses automatic updates and checks for newer edits/runtime incompatibility before restoration.

File ownershipUpdate behavior

updates/file_policy.py is the ownership authority. Add a new editable preference file to the appropriate policy, or put runtime state in the established private state directory. New settings also need sensible fresh-install defaults and preservation behavior.

The installed .xetal-update.json records the delivered revision, rendered defaults and ownership information. Clone installs use their actual checkout commit; ZIP installs use exported source revision metadata. The delivered revision must not be replaced with the remote's latest HEAD merely to clear an update badge.

Local development and update records: copying a few files into the live profile is not a complete registered release. Use the normal installer/update flow where appropriate. If a coordinated development deployment is required, back up and verify the actual delivered files before updating its inventory; a newer checkout hash alone is insufficient.

Updater settings, status, prepared state and backups: ~/.local/state/xetal-hyprland/updates/. Downloads: ~/.cache/xetal-hyprland/updates/. Details: UPDATES.md. KVM component updates are a separate system.

10

Making a change that reaches users correctly

The usual working loop

  1. Inspect: reproduce the issue, find its wrapper/model/UI and read the nearby tests. Check both source and live versions. Record existing changes before editing.
  2. Implement: edit the tracked portable source; reuse shared theme, command dispatch and existing operation engines. Keep paths recipient-relative and preserve state formats or migrate them deliberately.
  3. Validate: run checks matching the affected behavior. Exercise real selection, keyboard, D-Bus and job lifetimes where relevant. Inspect the UI at practical sizes and in the relevant themes.
  4. Integrate: update the installer build/dependency list, default entries and update ownership if needed. Document behavior changes. A new favorite should be a clean install default, not an overwrite of every existing user's pins.
  5. Deploy when in scope: retain a private backup, update the required live files/build outputs, restart only the relevant idle helpers and verify the running result. Preserve user preferences and ongoing work.
  6. Review and publish when requested: inspect the exact staged diff and assets for private data. Finish required validation before pushing a release commit to main. Report local work, installation and publication separately.
A new Control Panel tool

Connect the card to real behavior

Start at tools.json and native.cpp. Add the page/backend under control_panel/, wire it into the backend CMake build and reuse its theme/window sizing helpers.

Administrative work belongs in a narrowly scoped helper with the existing authentication flow, not in a root-running GUI. Opening a tool should not execute its maintenance action.

A new setting or shell action

Follow the whole route

Find the owning Settings page, wrapper and persistent file. Preserve hotkey metadata, command quoting and session ownership. Update file_policy.py if the new saved file is a user preference.

Use generic folder dispatch when respecting Default Apps; use files.sh only when the action specifically requests Fusion Files.

Restarting a running UI

Apps, Settings and Control Panel may be preloaded and hidden. Rebuilding a binary or changing Python source does not replace code already loaded in that process. Identify the owning instance and ensure it is idle before restarting it. File copies, disk scans, package transactions and VM operations must be allowed to finish or use their normal cancellation path.

Floating header dragging: scripts/floating-drag.py owns the invisible top grip. Its drag_cursor.py guard leaves text selection with the application, including when a held gesture leaves the field. The read-only runtime/cursor_probe adapter supplies named cursor shapes and fingerprints of legacy cursor images through hyprctl xetal-cursor. Only recognized ordinary pointers permit the grip; unavailable or unknown cursors defer to the app. Super-drag keeps working. Build this adapter for the pinned runtime, and run tests/check-floating-text-drag.py for real selection/header-drag coverage in an isolated compositor.

For compositor effects, use the supported session lifecycle instead of swapping native plugins mid-session. After local deployment, launch through the real wrapper and verify the actual running UI, not just an offscreen test window.

These are entry points, not a requirement to run every expensive suite for every small edit. Run commands from the repository root with the documented dependencies installed. Native output and private test fixtures must stay out of commits.

Public source, private state

The development machine is personal. The release payload is portable. Keep that separation explicit whenever moving files between them.

Location / classMeaning and handling

~/.config/hypr/The live installation. It combines delivered code, rendered paths, personalized configuration, generated files and private state. Never copy the entire tree back into the public checkout.
file_manager/state/Bookmarks, custom menu actions, columns, sidebar state and geometry in settings.ini. Keep private, exclude from new installs, preserve across updates.

.gitignore is one boundary. installer/install.py → payload_ignored() separately excludes runtime data from copies; it also regenerates clean launcher defaults even if source was used as a desktop. updates/file_policy.py and the update engine define preservation. KVM has a separate delivery model

The repo contains the integrated editor/backend, portable defaults and signed component metadata. QEMU, firmware, TPM, OpenCore, Looking Glass, custom module and baseline support packages are downloaded through KVM Settings when requested. Their signatures, sizes and hashes are checked before extraction; writable guest state is seeded separately and preserved. A desktop update does not replace a user's VM disk or identity.

The component service's private token and publisher signing keys never belong in this repo. Physical disks, PCI/USB passthrough and GPU ROM choices are recipient-specific. See KVM.md for compatibility, network/GPU behavior and actual-host testing requirements.

Assets and source provenance

The project has an MIT license, while bundled components retain their own terms. The CachyOsTools backend records its revision and GPL license in control_panel/UPSTREAM.json; KVM records its backend origin separately. Artwork, fonts, native effects and packaged runtimes have their own notices. Preserve third-party notices, licenses and asset provenance when moving or adding resources.

Some signed distribution runtime bundles are intentionally tracked. That does not make arbitrary generated binaries or local KVM runtime payloads appropriate release files. Inspect exact staged paths rather than adding a whole live directory.
