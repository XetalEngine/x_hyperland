Run `./x_hyperinstall.sh --check` before installing. The package recipes are in [`installer/dependencies.py`](../installer/dependencies.py); the same file checks executable versions, Python imports, development libraries, Qt private headers and the portal/authentication helpers.

The custom Waybar modules use its CFFI v2 interface and its 0.15 workspace taskbar structure. Qt theme plugins use private APIs and are built against the installed Qt versions; session startup checks and rebuilds them after Qt changes. Their source is included.

The current release pins **Hyprland 0.56.2**, commit `efb50993780079460b0cbed1363e2166a2de1d9f`. Arch-family Setup supplies the complete signed runtime in [`runtime/arch.json`](../config/hypr/runtime/arch.json): the compositor, its matching libraries, headers and companion tools. Current repositories have Aquamarine ABI 15 and Hyprgraphics ABI 5; this build requires ABI 14 and ABI 4. The matching packages are bundled and can also be fetched automatically from the official archive with checksum and signature verification. All twelve runtime packages are held through `/etc/pacman.d/xetal-hyprland.conf`.

The remaining desktop/build dependencies are fetched through the recipient's own distribution repositories. On Arch-family systems, Setup resolves and applies a coordinated full package upgrade with the matching runtime, rather than mixing a pinned compositor with whatever library ABI the mirrors currently offer. An older Python interpreter is restarted after a major/minor Python upgrade, preserving the setup arguments and runtime recovery record. Dependency/conflict checks remain enabled. See [Setup and recovery](INSTALLER.md).

For systems that have not been updated recently, Setup first updates the installed distribution signing-key packages using normal signature verification. This follows Arch's [keyring-before-system-upgrade procedure](https://wiki.archlinux.org/title/Pacman/Package_signing#Upgrade_system_regularly); it also retains the Manjaro, CachyOS or EndeavourOS keyring when installed. The one-year-old bootstrap test reproduced unknown-trust errors without this step. Keyring updates are trust-data updates and remain installed if subsequent runtime setup fails.

The earlier [0.57 Lua compatibility layer](https://github.com/hyprwm/Hyprland/releases/tag/v0.57.0) remains in the source for future adapter work. Its presence does not make 0.57 an accepted compositor for this release. Native effects and configuration must all validate against the manifest's exact version before activation.

The compatibility `hyprctl` lives inside the profile and is inherited only by applications launched through this desktop's commands. It translates legacy desktop actions and live settings to Lua; native queries pass through. It does not replace `/usr/bin/hyprctl`, change shell profiles, or export its PATH to D-Bus/systemd. Hyprland 0.56.2 continues to use its native `.conf` entry point.

The pinned Hyprland 0.56.2 release supports our managed `.conf` format. Hyper Fusion acknowledges its repeated format-migration reminder before the first desktop frame using a small ABI-checked [startup adapter](../config/hypr/runtime/notices/plugin.cpp). It matches the exact localized notice through Hyprland's notification API; configuration errors and other warnings remain visible. The separate missing-`hyprland-guiutils` reminder is disabled with Hyprland's `misc:disable_hyprland_guiutils_check` setting. Setup and updates build the adapter with the installed compositor headers, and the profile loads it on every login. This does not migrate the profile to 0.57 or provide the optional upstream dialog utility.

The C++ [Control Panel](CONTROL-PANEL.md) builds from the included CachyOsTools engine. Its Arch-specific system/ISO tools retain their own runtime requirements. Qt SVG supplies its themed icons; translation build tools are packaged as `qt6-tools` on Arch, [qt6-qttools-devel/qt6-linguist on Fedora](https://packages.fedoraproject.org/pkgs/qt6-qttools/), and `qt6-tools-dev` plus [qt6-l10n-tools on Debian](https://packages.debian.org/sid/utils/qt6-l10n-tools).

The Control Panel build uses every CPU available to the installer, including logical threads, and prints the parallel job count. The installer also prints its source revision and checks the complete configuration before compilation, then validates the built profile again before activation.

Its integrated [Proton page](../config/hypr/control_panel/proton/README.md) adds
libcurl >= 7.85, libarchive and OpenSSL Crypto development dependencies. Setup
uses `curl`/`libarchive` on Arch, `libcurl-devel`/`libarchive-devel` on Fedora, and
`libcurl4-openssl-dev`/`libarchive-dev` on Debian, alongside the existing OpenSSL
and Qt Concurrent packages. `cabextract` is supplied for Winetricks components.
Proton and UMU are downloaded separately when requested in Control Panel.

The private GTK 3 preview module is built by the same theme builder. Qt previews use Qt Concurrent for background loading; both dependencies are supplied by the existing GTK/Qt development package recipes. See [file picker coverage](FILE-PREVIEWS.md).

### XWayland and VLC startup

Setup explicitly installs the X11 compatibility package group on Arch-family systems, Fedora and Debian. The server packages are `xorg-xwayland`, `xorg-x11-server-Xwayland` and `xwayland`, respectively. The client libraries include the [Qt XCB requirements](https://doc.qt.io/qt-6/linux-requirements.html), plus Xpresent and other common runtime libraries used by bundled applications. Setup checks that each required shared library can load and reports missing libraries or loader errors before activating the desktop. These packages cover common X11 client requirements; individual applications can still need additional dependencies.

Hyprland starts XWayland and supplies its `DISPLAY` value. Native Wayland applications retain their Wayland backends; Setup does not force an X11 backend globally or install a separate Xorg desktop session.

VLC 3.0.24's [Qt interface checks X11 before opening and selects the xcb backend](https://github.com/videolan/vlc/blob/3.0.24/modules/gui/qt/qt.cpp). A working native Wayland desktop does not prove that this X11 compatibility connection works. Do not force `QT_QPA_PLATFORM=xcb` globally to fix one application.

The [session helper](../config/hypr/scripts/xwayland-session.py) watches this compositor's X11 socket. With abstract sockets disabled, [Hyprland 0.56.2 creates both `X<N>` and `X<N>_`](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/xwayland/Server.cpp). If the standard pathname disappears but the backup listener is alive, the helper restores access with a hard link to that socket. Unlike a user-owned symlink in the root-owned sticky X11 directory, the socket link also works for authenticated root applications when Linux protected-symlink rules are enabled. It checks the display lock, ownership, file types, socket identity and peer credentials against the live compositor IPC connection. It leaves existing files and sockets intact; its only migration is a verified legacy symlink pointing to this exact backup. It never restarts XWayland, changes access-control rules, or changes another desktop's environment. It exits when the compositor disconnects; no persistent user service is installed.

Run `python3 ~/.config/hypr/scripts/xwayland-session.py --check` for a read-only diagnosis. The helper's transition log is `xwayland-session.log` in the current Hyprland runtime directory, subject to the existing session logging preference. If both listeners are lost, this helper reports the problem; it cannot recreate the server's listening descriptors without restarting the session. Save work before logging out in that situation.

Administrator GUI shortcuts use **Apps → right-click shortcut → Properties → Run as administrator**. Enter the actual program command without `sudo`. The profile-local `scripts/xsudo.sh` / `gui-admin.py` wrapper repairs the verified display endpoint when necessary, requests authentication, selects XWayland only for that elevated process, and leases `SI:localuser:root` display access until the last concurrent launch exits. Existing display grants remain unchanged. From a Hyprland terminal, use `~/.config/hypr/scripts/xsudo.sh PROGRAM [arguments...]`; raw `sudo` alone does not provide display authorization. Never use `xhost +` or disable `fs.protected_symlinks`. Bundled applications can also report independent font-cache or Qt compatibility warnings; diagnose those separately from a failed X11 connection.

Tests must use offscreen Qt, disposable sockets outside `/tmp/.X11-unix`, or a nested compositor with XWayland disabled. Never unlink or rename the active display's sockets or locks to make room for a test display. Socket recovery tests exercise missing paths, conflicting entries, stale listeners, mismatched ownership/identity and session shutdown entirely in a temporary directory.

The **Compiz Burn** close effect supports Hyprland **0.56.2** at the tested commit documented in [its guide](../config/hypr/effects/burn/README.md), x86-64 and the OpenGL renderer. It needs a C++23 compiler, matching Hyprland development headers exposed through `pkg-config hyprland`, and GLESv2 development files. Its build and runtime ABI checks reject mismatched versions. Setup requires a successful build; the effect itself remains configurable in **Theme → Window effects → Burn**.

**Desktop Cube & 3D Windows** uses the same tested Hyprland ABI and C++23/OpenGL requirements as Burn, plus json-c and libei development headers (`json-c`, `libeis-1.0`). Its sources and required build are included in the installer. A missing dependency or failed build stops the new installation before replacing the profile. See the [Cube guide](../config/hypr/effects/cube/README.md).

**Fireball Minimize** uses the same pinned ABI, OpenGL renderer and `libeis-1.0` headers. Its required adapter also supplies workspace-aware Front/Back ordering. See the [Minimize guide](../config/hypr/effects/minimize/README.md).

Xetal Images uses the installed Qt image readers. Common image formats are included with Qt; additional readers such as HEIF, AVIF, camera RAW and PSD depend on the distribution's Qt image-format plugins.

Xetal Files speaks the [KDE JobView interfaces](https://invent.kde.org/frameworks/kjobwidgets) used by Dolphin/KIO and Ark. It starts only for this Hyprland session and leaves any existing job-service owner in charge. Applications that draw their own progress windows independently of these interfaces retain their own UI. No KDE configuration or system service is replaced.

The media popup can update its private copy from the [official yt-dlp releases](https://github.com/yt-dlp/yt-dlp/releases), with SHA-256 verification and an atomic replacement. Current YouTube extraction also needs the [EJS scripts and a supported JavaScript runtime](https://github.com/yt-dlp/yt-dlp/wiki/EJS). The official update archive includes EJS; Deno, Node.js or QuickJS and FFmpeg remain distribution dependencies.

Automatic compositor installation supports Arch-based x86-64, mutable Fedora 44 x86-64 and Debian 13 amd64 systems. Fedora uses its own signed RPM bundle, including matching headers/libraries and DNF version locks; see [Fedora setup](INSTALLER.md#fedora-44). Debian 13 uses a separate 22.3 MB native DEB bundle, with matching libraries, headers and dedicated APT pins; see [Debian setup](INSTALLER.md#debian-13). Other distributions, including Ubuntu, must supply the exact native manifest version and commit themselves. Repository availability differs by release. On Arch, Setup uses the official Arch archive; on Fedora 44 it uses the bundled signed COPR RPMs. Arch and Fedora retain their normal package signature checks. Debian verifies the bundled native files against its trusted release manifest and uses authenticated APT repositories for ordinary dependencies. All paths retain dependency checks, without adding a third-party package repository or forcing incompatible libraries. Manual dependency installations can use `--skip-packages` after satisfying the same checks.

Before any compositor change, initial Setup and foreground updates check the OS family, architecture and package tools. Arch preflight resolves the matching runtime, desktop packages and system upgrade together in pacman's print mode, including minimum versions of Waybar, Kitty and Hyprpaper. Missing dependencies are selected for installation automatically; an unresolved package conflict stops before changing the compositor. Fedora 44 resolves its matching RPMs and desktop packages with DNF, and Debian 13 resolves its native bundle with APT. Unsupported releases, immutable OSTree desktops and non-x86-64 hardware receive an early explanation.

On Arch, a failed package check includes both pacman output streams in Installation details and `~/.local/state/xetal-hyprland/setup.log`. Preflight refreshes a disposable copy of the configured repository metadata and combines it with the real installed package database and verified runtime bundle. It does not change host packages or host repository databases. The line naming a conflict can be on standard output even when the summary is on standard error; both are retained.

The [installer compatibility workflow](../.github/workflows/installer-compatibility.yml) checks current Arch, CachyOS v3/v4, EndeavourOS and Manjaro stable repositories, plus upgrades from real Arch package metadata dated **2025-11-05** and **2026-05-05**. Reproduce the one-year and six-month checks with `python3 tests/repository_matrix.py --distro arch --historical 2025/11/05 --historical 2026/05/05 --output repository-report.json`. Historical tests populate installed-package records for the old desktop and its transitive dependencies, then resolve the complete upgrade against today's repositories; they do not merely test an empty root. These read-only matrix checks never change host packages.

Separate disposable-container jobs perform actual Arch installation, dependency checks, native effect builds and recovery, both from a fresh base and from a newer upstream Hyprland. The historical installation job starts from the official **2025-11-01 bootstrap** with **2025-11-05 packages**, then upgrades to current repositories and runs the same tests. Local validation on 2026-11-05 passed from Python 3.13.7, pacman 7.0 and the 20251027 keyring: all required dependencies installed, Burn/Cube/Minimize built, and both normal recovery and injected-failure recovery succeeded. The authentication suite also tests missing-sudo selection and a real su/PAM password exchange in a disposable filesystem.

An additional historical bootstrap check started without Python or sudo and successfully installed Python 3.14.9 through the prerequisite helper. On current Arch, the complete installer `--prepare` build passed: Qt theme plugins, Control Panel, Fusion Files, Waybar modules, capture helpers, cursors/icons and all four native effects, followed by full configuration validation. That run also verified restoring the newer upstream runtime and recovery after an injected failure. CI repeats full builds from both historical prerequisite variants and fresh/current Arch bases.

Fedora 44 and Debian 13 retain their native installation/build/recovery jobs. These checks establish specific tested package combinations; graphical login, GPU/driver behavior, arbitrary third-party packages and older Fedora/Debian major releases still require their own validation. Setup never treats an unsupported release as compatible just by disabling dependency checks.

Recent rolling distributions are the easiest match. Older stable distribution releases may ship Hyprland/Waybar/Kitty versions below the requirements. A successful package-manager command alone does not bypass the subsequent version and build checks.

Hardware modes are captured only from the recipient's running compositor. Without that connection, preferred-mode auto placement is used. The included original DP-4/DP-5/DP-6 profile is explicit opt-in. Ordinary Linux home paths are supported; paths containing spaces or configuration metacharacters are rejected before any files are copied, because the upstream configuration formats interpret those characters differently.

KVM Settings uses OpenSSL for signed package verification, `remote-viewer` (virt-viewer) for SPICE/VNC consoles, `virt-fw-vars` for UEFI display preferences, and GnuTLS `certtool` for private TPM certificate generation. These are included in the distribution recipes, together with GCC/C++, make, CMake, autoconf/automake/libtool, Perl, gettext, gawk, expect, socat, OpenSSL/GnuTLS, libtasn1, GMP, GLib, libseccomp, FUSE and libei development packages. Hardware and image tools include tpm2-tools, dmidecode, pciutils, usbutils, mtools, dosfstools, util-linux and kmod. Capability checks verify these tools before installation. Downloaded KVM runtime components do not require rebuilding. The QEMU bundle's SDL compatibility library also loads the host SDL3 runtime; Fedora's recipe explicitly installs `SDL3`, and the Debian 13 bundle supplies a newer native `libsdl3-0`, rather than relying on another desktop package to pull it in. Custom source rebuilds still require the matching source checkout; private development trees are not shipped. The published custom kernel module supports only its listed AMD/kernel combination.

On Arch, the [`perl` package](https://archlinux.org/packages/core/x86_64/perl/files/) provides `pod2man` under `/usr/bin/core_perl`. The installer and update builder add existing Perl script directories to their own process PATH before checking dependencies, including after package installation. This works in a terminal opened before Perl was installed without changing shell profiles or requiring another login. To retry an older downloaded installer that stopped at `Missing command: pod2man`, run `PATH="$PATH:/usr/bin/core_perl" ./x_hyperinstall.sh` from its extracted directory.

`virt-fw-vars` is provided by `virt-firmware` on Arch and `python3-virt-firmware` on [Fedora](https://packages.fedoraproject.org/pkgs/python-virt-firmware/python3-virt-firmware/) and [Debian](https://ftp.debian.org/debian/pool/main/v/virt-firmware/). The terminal emblem uses the same Qt SVG bindings already used by the desktop; rendered PNGs are cached in the recipient's cache directory.
