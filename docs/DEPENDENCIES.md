# Dependencies and portability

Run `./x_hyperinstall.sh --check` before installing. The package recipes are in [`installer/dependencies.py`](../installer/dependencies.py); the same file checks executable versions, Python imports, development libraries, Qt private headers and the portal/authentication helpers.

| Area | Required components |
| --- | --- |
| Desktop | Exact Hyprland 0.56.2 and commit from the runtime manifest; Hyprpaper 0.8+, Hyprlock, Waybar 0.15+, Kitty 0.49+ (0.47.1+ on Fedora 44, 0.48.2+ on Debian 13), Dolphin, Konsole's Qt 6 embedded terminal, SwayNotificationCenter |
| Python | Python 3.11+, PyQt6 Widgets/Network/DBus/SVG, PyGObject with Gio/GTK 3/GtkLayerShell, Pillow |
| Native builds | C/C++23 compiler, matching Hyprland headers, GLESv2, json-c, libei, CMake, pkg-config, GTK 3, gio-unix, gtk-layer-shell, json-glib, Wayland client/scanner; Qt 5 and 6 Widgets/Concurrent, Qt Network/DBus/Linguist, development tools and private QtGui/QtCore headers; XCB and XCB-RES |
| Capture | grim, slurp, wl-clipboard, wf-recorder, FFmpeg/ffprobe, xdg-desktop-portal-hyprland, GTK desktop portal |
| Audio | PipeWire PulseAudio compatibility, pactl, WirePlumber/wpctl, playerctl |
| Media downloader | yt-dlp, FFmpeg/ffprobe, and a supported Deno, Node.js or QuickJS runtime; wl-paste for selected links |
| Network | NetworkManager/nmcli, network-manager-applet, nm-connection-editor, BlueZ/bluetoothctl, Blueman |
| Desktop updates | Git, Python standard-library HTTPS, access to the GitHub repository; native builds use the dependencies above. No automatic system-package installation. |
| Session/tools | libnotify/notify-send, GDBus, GNOME PolicyKit agent (Hyprpolkitagent on Fedora 44 and Debian 13), xdg-utils, xdg-user-dirs, util-linux/flock, procps/pgrep, brightnessctl, Fastfetch, htop, sudo and xhost for elevated graphical tools |

The custom Waybar modules use its CFFI v2 interface and its 0.15 workspace taskbar structure. Qt theme plugins use private APIs and are built against the installed Qt versions; session startup checks and rebuilds them after Qt changes. Their source is included.

The current release pins **Hyprland 0.56.2**, commit `efb50993780079460b0cbed1363e2166a2de1d9f`. Setup installs the official signed Arch `0.56.2-4` package when needed, including a downgrade from 0.57, and holds it through `/etc/pacman.d/xetal-hyprland.conf`. Normal dependency installation excludes Hyprland so it cannot immediately undo the pin. Package dependency checks remain enabled; incompatible system libraries stop installation. See [Setup and recovery](INSTALLER.md).

The earlier [0.57 Lua compatibility layer](https://github.com/hyprwm/Hyprland/releases/tag/v0.57.0) remains in the source for future adapter work. Its presence does not make 0.57 an accepted compositor for this release. Native effects and configuration must all validate against the manifest's exact version before activation.

The compatibility `hyprctl` lives inside the profile and is inherited only by applications launched through this desktop's commands. It translates legacy desktop actions and live settings to Lua; native queries pass through. It does not replace `/usr/bin/hyprctl`, change shell profiles, or export its PATH to D-Bus/systemd. Hyprland 0.56.2 continues to use its native `.conf` entry point.

The pinned Hyprland 0.56.2 release supports our managed `.conf` format. Hyper Fusion acknowledges its repeated format-migration reminder before the first desktop frame using a small ABI-checked [startup adapter](../config/hypr/runtime/notices/plugin.cpp). It matches the exact localized notice through Hyprland's notification API; configuration errors and other warnings remain visible. The separate missing-`hyprland-guiutils` reminder is disabled with Hyprland's `misc:disable_hyprland_guiutils_check` setting. Setup and updates build the adapter with the installed compositor headers, and the profile loads it on every login. This does not migrate the profile to 0.57 or provide the optional upstream dialog utility.

The C++ [Control Panel](CONTROL-PANEL.md) builds from the included CachyOsTools engine. Its Arch-specific system/ISO tools retain their own runtime requirements. Qt SVG supplies its themed icons; translation build tools are packaged as `qt6-tools` on Arch, [qt6-qttools-devel/qt6-linguist on Fedora](https://packages.fedoraproject.org/pkgs/qt6-qttools/), and `qt6-tools-dev` plus [qt6-l10n-tools on Debian](https://packages.debian.org/sid/utils/qt6-l10n-tools).

The Control Panel build uses every CPU available to the installer, including logical threads, and prints the parallel job count. The installer also prints its source revision and checks the complete configuration before compilation, then validates the built profile again before activation.

The private GTK 3 preview module is built by the same theme builder. Qt previews use Qt Concurrent for background loading; both dependencies are supplied by the existing GTK/Qt development package recipes. See [file picker coverage](FILE-PREVIEWS.md).

The **Compiz Burn** close effect supports Hyprland **0.56.2** at the tested commit documented in [its guide](../config/hypr/effects/burn/README.md), x86-64 and the OpenGL renderer. It needs a C++23 compiler, matching Hyprland development headers exposed through `pkg-config hyprland`, and GLESv2 development files. Its build and runtime ABI checks reject mismatched versions. Setup requires a successful build; the effect itself remains configurable in **Theme → Window effects → Burn**.

**Desktop Cube & 3D Windows** uses the same tested Hyprland ABI and C++23/OpenGL requirements as Burn, plus json-c and libei development headers (`json-c`, `libeis-1.0`). Its sources and required build are included in the installer. A missing dependency or failed build stops the new installation before replacing the profile. See the [Cube guide](../config/hypr/effects/cube/README.md).

**Fireball Minimize** uses the same pinned ABI, OpenGL renderer and `libeis-1.0` headers. Its required adapter also supplies workspace-aware Front/Back ordering. See the [Minimize guide](../config/hypr/effects/minimize/README.md).

Xetal Images uses the installed Qt image readers. Common image formats are included with Qt; additional readers such as HEIF, AVIF, camera RAW and PSD depend on the distribution's Qt image-format plugins.

Xetal Files speaks the [KDE JobView interfaces](https://invent.kde.org/frameworks/kjobwidgets) used by Dolphin/KIO and Ark. It starts only for this Hyprland session and leaves any existing job-service owner in charge. Applications that draw their own progress windows independently of these interfaces retain their own UI. No KDE configuration or system service is replaced.

The media popup can update its private copy from the [official yt-dlp releases](https://github.com/yt-dlp/yt-dlp/releases), with SHA-256 verification and an atomic replacement. Current YouTube extraction also needs the [EJS scripts and a supported JavaScript runtime](https://github.com/yt-dlp/yt-dlp/wiki/EJS). The official update archive includes EJS; Deno, Node.js or QuickJS and FFmpeg remain distribution dependencies.

Automatic compositor installation supports Arch-based x86-64, mutable Fedora 44 x86-64 and Debian 13 amd64 systems. Fedora uses its own signed RPM bundle, including matching headers/libraries and DNF version locks; see [Fedora setup](INSTALLER.md#fedora-44). Debian 13 uses a separate 22.3 MB native DEB bundle, with matching libraries, headers and dedicated APT pins; see [Debian setup](INSTALLER.md#debian-13). Other distributions, including Ubuntu, must supply the exact native manifest version and commit themselves. Repository availability differs by release. On Arch, Setup uses the official Arch archive; on Fedora 44 it uses the bundled signed COPR RPMs. Arch and Fedora retain their normal package signature checks. Debian verifies the bundled native files against its trusted release manifest and uses authenticated APT repositories for ordinary dependencies. All paths retain dependency checks, without adding a third-party package repository or forcing incompatible libraries. Manual dependency installations can use `--skip-packages` after satisfying the same checks.

Before any compositor change, initial Setup and foreground updates check the OS family, architecture and package tools, resolve the desktop dependencies against the machine's configured repositories, and check the repository versions of Waybar, Kitty and Hyprpaper. Pacman's print mode also checks the pinned compositor's dependencies against the installed system before requesting administrator authentication. A missing package or incompatible library stops setup with the current compositor unchanged. Fedora 44 resolves the bundled RPMs and desktop packages with DNF before installing. Other unsupported systems without the exact native compositor, unsupported package managers, immutable OSTree desktops and non-x86-64 hardware receive an early explanation.

On Arch, a failed package check includes both pacman output streams in Installation details and `~/.local/state/xetal-hyprland/setup.log`. The line naming the missing or conflicting dependency can be on standard output even when the generic error is on standard error. Include those package-specific lines when reporting a failure; the generic “could not satisfy dependencies” message alone does not identify the cause. These checks do not refresh databases, remove packages or disable dependency checking.

The [installer compatibility workflow](../.github/workflows/installer-compatibility.yml) checks current Arch, CachyOS v3/v4, EndeavourOS and Manjaro stable repositories, and installs/builds/recovers the Fedora 44 and Debian 13 desktops in disposable containers, on installer changes and weekly. Run `python3 tests/repository_matrix.py --output repository-report.json` on an Arch-family system to reproduce it. The Arch matrix uses disposable package databases and `--print`; it never changes host packages. The Fedora job changes packages only inside its disposable CI container and checks builds plus rollback. These checks cover package availability, minimum versions and the pinned package's declared dependencies. It does **not** replace VM login, native build, GPU/driver or physical-hardware testing, and is not a promise of support for every Linux distribution or future repository update.

Recent rolling distributions are the easiest match. Older stable distribution releases may ship Hyprland/Waybar/Kitty versions below the requirements. A successful package-manager command alone does not bypass the subsequent version and build checks.

Hardware modes are captured only from the recipient's running compositor. Without that connection, preferred-mode auto placement is used. The included original DP-4/DP-5/DP-6 profile is explicit opt-in. Ordinary Linux home paths are supported; paths containing spaces or configuration metacharacters are rejected before any files are copied, because the upstream configuration formats interpret those characters differently.

KVM Settings uses OpenSSL for signed package verification, `remote-viewer` (virt-viewer) for SPICE/VNC consoles, `virt-fw-vars` for UEFI display preferences, and GnuTLS `certtool` for private TPM certificate generation. These are included in the distribution recipes, together with GCC/C++, make, CMake, autoconf/automake/libtool, Perl, gettext, gawk, expect, socat, OpenSSL/GnuTLS, libtasn1, GMP, GLib, libseccomp, FUSE and libei development packages. Hardware and image tools include tpm2-tools, dmidecode, pciutils, usbutils, mtools, dosfstools, util-linux and kmod. Capability checks verify these tools before installation. Downloaded KVM runtime components do not require rebuilding. The QEMU bundle's SDL compatibility library also loads the host SDL3 runtime; Fedora's recipe explicitly installs `SDL3`, and the Debian 13 bundle supplies a newer native `libsdl3-0`, rather than relying on another desktop package to pull it in. Custom source rebuilds still require the matching source checkout; private development trees are not shipped. The published custom kernel module supports only its listed AMD/kernel combination.

On Arch, the [`perl` package](https://archlinux.org/packages/core/x86_64/perl/files/) provides `pod2man` under `/usr/bin/core_perl`. The installer and update builder add existing Perl script directories to their own process PATH before checking dependencies, including after package installation. This works in a terminal opened before Perl was installed without changing shell profiles or requiring another login. To retry an older downloaded installer that stopped at `Missing command: pod2man`, run `PATH="$PATH:/usr/bin/core_perl" ./x_hyperinstall.sh` from its extracted directory.

`virt-fw-vars` is provided by `virt-firmware` on Arch and `python3-virt-firmware` on [Fedora](https://packages.fedoraproject.org/pkgs/python-virt-firmware/python3-virt-firmware/) and [Debian](https://ftp.debian.org/debian/pool/main/v/virt-firmware/). The terminal emblem uses the same Qt SVG bindings already used by the desktop; rendered PNGs are cached in the recipient's cache directory.
